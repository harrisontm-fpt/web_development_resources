# Session 01 workshop — Establish your team

[Lecture](lecture.md) · [Session index](../README.md)

**60-minute workshop + 60-minute project block · Ungraded**

## Before you start

Open your brief, or use the campus activities scenario in the lecture. You need a shared document and Trello access. Select a facilitator, recorder, and challenger; rotate these responsibilities next time. The challenger checks assumptions rather than simply disagreeing.

## Step 1 — Understand the problem (0–15 minutes)

Read the brief individually for three minutes. Together, write:

1. The primary user and the task they need to complete.
2. The difficulty with the current process.
3. One observable sign that your project would help.
4. Three questions you cannot answer from the brief.

Mark each claim **confirmed** or **assumed**. For example, “Visitors must register” is an assumption until supported by the brief/client. Choose an owner to follow up each question.

## Step 2 — Agree how to work (15–35 minutes)

Copy the team-agreement table from the [management workbook](../../project_management.md). Fill every row that you can now. Agree a weekly meeting, realistic availability, a communication channel, absence/blocker handling, and how you resolve disagreements.

Decide how someone requests help after becoming stuck. Avoid “we will communicate well”: write a behaviour such as “post the failing request, what was expected, and what has already been tried.”

Each member states one skill they can contribute and one they want to practise. Arrange shared technical work rather than permanent coder/designer/presenter roles.

## Step 3 — Create a visible board (35–50 minutes)

Create lists: **Backlog → Ready → In progress → Review/Test → Done**. Add a visible Blocked label. Invite all members and give the lecturer the required viewing access.

Create at least five useful starter cards: clarify a requirement, set up the repository, sketch a user journey, investigate a technical dependency, and draft the proposal. Adapt these to the brief. Add an owner and an observable finish condition to each. Move only work you can actually start to Ready.

## Step 4 — Check the plan (50–60 minutes)

Read another team's objective and one task. Ask:

- What will we be able to see when this is complete?
- What might stop it?
- Who will follow it up?

Revise one vague task using that feedback. Record your first weekly objective.

## Evidence to keep

- [ ] Team agreement and available hours.
- [ ] Shared board link with clear lists and starter cards.
- [ ] Problem statement and confirmed/assumed notes.
- [ ] Client questions with owners.
- [ ] One demonstrable weekly objective.

Store links in your shared workspace now; add them to the project README when the repository exists.

## Project block (60 minutes)

Use 5 minutes to choose an immediate goal, 45 minutes to work, and 10 minutes to update the board. Obtain missing brief information, agree communication, and prepare repository access for session 2.

**If blocked:** document the missing brief/access and practise with the campus scenario. Keep its assumptions separate from your real brief.
**If finished early:** identify a dependency between two cards and agree which must happen first.
**Exit question:** Can every member explain the same user problem without reading the brief?
