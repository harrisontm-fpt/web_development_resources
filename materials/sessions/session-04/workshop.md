# Session 04 workshop — Prototype and test a journey

[Lecture](lecture.md) · [Session index](../README.md)

**60-minute workshop + 60-minute project block · Ungraded scope/design check**

## Before you start

Bring the prioritised backlog and one essential journey. Use paper or a shared drawing tool. Open the [UX workbook](../../ux_workbook.md). Assign a sketcher, flow reviewer, and recorder; all members contribute design decisions.

## Step 1 — Draw the task flow (0–10 minutes)

Write the user's goal and starting point. Draw the screens/actions needed to finish. Add at least one relevant alternative: no results, invalid input, missing record, or failed request.

Check the journey against an acceptance criterion from your backlog. If it describes an optional feature, select an essential journey instead.

## Step 2 — Sketch the screens (10–35 minutes)

Create low-fidelity mobile and desktop layouts for the main screens. Include:

- Representative headings and content.
- The main action and navigation.
- Visible labels and instructions for any form.
- The relevant alternative state identified above.

Connect screens so another person can follow the interaction. Mark unresolved content or requirements. Avoid spending the workshop selecting fonts or adjusting decorative details.

## Step 3 — Exchange a tester (35–50 minutes)

Use a three-team rotation: A sends a tester to B, B to C, C to A. Remaining members host and record.

Give a neutral task without naming controls. The tester explains expectations; the host reveals the next paper screen or lets them use the prototype. Do not correct the tester immediately when they choose an unexpected route.

Record what they did, whether they completed the task independently, and where they hesitated. Note device/layout and that this was peer feedback.

## Step 4 — Revise from evidence (50–60 minutes)

Choose one consequential finding. Write:

1. The observation.
2. Your interpretation.
3. The change you made.
4. How you would retest it.

Capture both the original and revised design. If no issue emerged, test the alternative state and record why you retained the design instead of inventing a defect.

## Evidence to keep

- [ ] Task flow for an essential journey.
- [ ] Mobile and desktop wireframes, with relevant alternative states.
- [ ] Neutral test task and observation notes.
- [ ] Revision or evidence-based decision to retain the design.
- [ ] Links added to the proposal.

## Project block (60 minutes)

Use 5 minutes planning, 45 completing the designs/proposal, and 10 reviewing the board. Include technical feasibility, exclusions, responsibilities, and open questions in the proposal.

**Due next session:** the proposal is submitted or made accessible before session 5. It is mandatory and ungraded.
**If blocked:** use representative content clearly labelled as provisional; do not stall all layout work waiting for final text.
**If finished early:** have someone attempt the journey using only the mobile wireframes and inspect how errors affect it.
**Exit question:** Which design decision changed because of something a tester actually did?
