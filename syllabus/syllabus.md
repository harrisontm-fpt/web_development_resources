### Aims

This course aims to combine many of the skills you have learned up to this point. You will complete a meaningful, industry-relevant full-stack web application, combining front-end development, back-end development, databases, UI/UX, automated testing, and project management skills.

### Objective

The student is able to define, design, implement, and test secure full-stack web applications.

### Content

* Implementing a full-stack web application
* Cloud platforms
* Security of web applications
* Testing of web applications
* Distributed version control systems
* Team collaboration, project planning, prioritisation, and scope control
* User research, wireframes, responsive UI, and usability evaluation
* Applying React, Express, and SQL learning from the adjacent WSK course

## Assessment

### A. Assessment Overview and Scale

See the [final assignment](final_assignment.md) for requirements and the [review and delivery checklists](../materials/reviews_and_delivery.md) for preparation.

The project proposal and progress reviews in weeks **4 and 7** are mandatory but **ungraded**. Additional classroom check-ins provide formative feedback. There are no separate numerical marks or percentage weights for these milestones.

The final application, presentation, and supporting evidence inform the final course grade. Passing grades are **1–5**; **0** indicates failure. Overall quality, completeness, robustness, and demonstrated understanding matter more than the number of additional features.

The final presentation takes place in session **16**. Final delivery is due **48 hours after session 16 ends**, allowing teams to respond to peer feedback. The lecturer will publish the corresponding calendar date, time, and timezone in the LMS before the course starts.

The evaluation scale for this course is **0-5**.

#### Assessment Criteria: Satisfactory (1)

The student:

* Has achieved the objectives of the course to a satisfactory level.
* Is able to identify, define, and use concepts and models in the subject area of the course.
* Has completed the learning tasks required for the course to the minimum standard.

#### Assessment Criteria: Good (3)

* Is able to identify, define, and use concepts, models, and tools in the subject area of the course.
* Has completed the learning tasks of the course at a good level.

#### Assessment Criteria: Excellent (5)

* Is able to identify, define, use, and apply concepts, models, and tools in the subject area of the course in a variety of ways.
* Has completed the learning tasks of the course at an excellent level and has put considerable personal effort into their solutions.

#### Assessment Criteria: Approved / Failed

The student:

* Has achieved the objectives of the course.
* Is able to identify the concepts and models in the subject area of the course.

### B. Minimum Requirements to Pass this Unit

To pass the course and receive at least a grade of **1**, a student must:

* Achieve the objectives of the course.
* Identify the core concepts and models.
* Complete all required mandatory learning tasks and projects.

### C. Use of Generative AI (GenAI) in this Unit

Generative AI tools such as ChatGPT and GitHub Copilot may be used. However, GenAI must not be used to generate the entirety of your project source code.

Students must:

* Be able to explain every line of code included in their submissions.
* Provide details of how and where GenAI tools were used.
* Provide examples of relevant prompts and outputs.
* Properly acknowledge any use of GenAI for core application logic in source code comments.

### D. Submission Requirements

All source code must be committed to the designated version control repository, such as GitHub or GitLab.

Submissions must:

* Follow any specified submission guidelines.
* Be committed to the designated repository.
* Be submitted through the university's LMS where required.

### E. Groupwork Guidelines

The final application project is completed in three teams working on separate client briefs, with a maximum of **three students per team**.

It is the collective responsibility of the group to:

* Manage the version control repository appropriately.
* Ensure all group members contribute fairly.
* Maintain clear evidence of individual contributions.

Individual Git commit histories, pull-request reviews, design work, testing, and other project evidence may be reviewed to assess individual contributions. Commit counts alone do not determine contribution. Every member must contribute technical work, attend the two formal reviews, and be able to explain their work.

### Academic Integrity

Academic integrity is about taking responsibility for your learning.

In a programming context, this means writing your own code and explicitly referencing external material that you incorporate into your work, including:

* External libraries
* Code snippets
* Stack Overflow solutions
* Tutorials
* AI-generated code or structures
* Other third-party sources

#### Plagiarism

**Plagiarism** includes submitting someone else's source code or work as your own.

#### Collusion

**Collusion** includes sharing your code with another student when individual work is required.

Breaches of academic integrity will be treated seriously and may result in a failing grade of **0** for the course.
